title: "Releases"
description: "How versions are cut with release-please, how the container image picks them up, and where the changelog lives."
---

Version numbers follow semver (`major.minor.patch`), and a tool called
release-please cuts each one from `master`. It reads the commit messages to
decide the bump: a commit starting with `feat:` bumps the minor number, one
starting with `fix:` bumps the patch number. Release-please keeps a release
pull request up to date with the version bump written into `pyproject.toml`
and the notes written into `CHANGELOG.md`. Merging that pull request creates
the `vX.Y.Z` tag and publishes the release.

The container image installs a release straight from its source tarball (a
zipped copy of the code that GitHub generates for every tag), so nothing extra
has to be attached to the release itself:

```
https://github.com/romm-streaming/romm-broker/archive/refs/tags/vX.Y.Z.tar.gz
```

Before version 1.0.0, even a breaking change (one that could require you to
change your setup) only bumps the minor number, not a major one. Moving to
1.0.0 is a deliberate decision, made by adding a `Release-As: 1.0.0` line to a
commit message.

## What a release triggers

1. The `release.yml` workflow runs release-please on every push to `master`.
   It keeps the release pull request up to date with the commits made since
   the last tag; merging that pull request creates the tag and the GitHub
   release.
2. linuxserver's docker-webstation pipeline checks for the latest release on
   a schedule. When that differs from the version baked into the published
   `webstation:romm` image, it rebuilds that image with `BROKER_RELEASE`
   pinned to the new tag. See
   [Inside the image](/docs/container/image-internals).
3. The `docs.yml` workflow rebuilds this site on every push to `master` that
   touches the docs or the broker's own code, so the developer reference
   always matches the current source.

## Changelog

The full history is in
[CHANGELOG.md](https://github.com/romm-streaming/romm-broker/blob/master/CHANGELOG.md)
at the repository root, and each
[GitHub release](https://github.com/romm-streaming/romm-broker/releases)
carries the same notes.
